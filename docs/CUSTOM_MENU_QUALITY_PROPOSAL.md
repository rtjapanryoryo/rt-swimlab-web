# Custom メニュー品質向上・プロポーザル

## 現状の課題

1. **カスタム出力が Quick よりチープ**
   - 汎用表現（「Cho 200m」「Kick 4×50m」）が多く、Quick テンプレのような具体性（SKPS、IM Order、｜1-4 Dec 等）が不足
   - 指導ポイント・狙いが抽象的になりがち

2. **W-up の過剰**
   - 現状：総距離の 12% → 5000m で 600m、8000m で 960m
   - 「2〜3段階」の指示で、Cho 200m → Cho 200m → Cho 200m のようにセグメントを積み上げて距離を稼ぐ傾向
   - Quick は 200〜600m、多くても 1〜2 セグメントで目的を持たせている（SKPS、mixed 等）

3. **項目数・本数の過剰**
   - 距離達成のために本数を増やしがち（Kick 20×50m、Drill 15×50m 等）
   - Quick は「少ない本数×長い距離」を活用（Pull 3×400m、Main 2×800m、Kick 4×200m）

---

## 提案方針

### A. プロフェッショナルな内容（Quick との整合）

| 観点 | 現状 | 目標（Quick レベル） |
|------|------|---------------------|
| W-up | 汎用 + 距離稼ぎ | SKPS、IM Order、Variable、Des、Build 等を必ず1つ以上 |
| Drill | 種目名のみ | 具体的ドリル名＋意図（例：片手キャッチアップ 6×50m｜DPS意識） |
| Kick/Pull | 本数×距離のみ | Des、Fins、DPS、Variable 等のパターン名を含む |
| Main | カテゴリ＋本数×距離 | Negative split、1H/1E Alt、レスト明示 等の具体的指示 |
| 指導ポイント | 汎用 | このメニューのブロックに即した具体的意識点（Quick 参照） |

**施策**: プロンプトに Quick テンプレの「良い例」を参照として追加。menu-dictionary の参照を強化。

---

### B. W-up の適正化（過剰防止）

| 現状 | 提案 |
|------|------|
| 12%・最低200m | **8%・上限500m**（目安） |
| 2〜3段階で距離を積む | **1〜2セグメントで十分**。2つ目は SKPS/IM/Variable 等の目的を持つ |

**根拠**: Quick テンプレの W-up は 200〜600m。プロの現場でも「ほぐし」は質重視。距離稼ぎは Main・Pull・Kick で行う。

**配分の変更案**:
- W-up: 12% → **8%**、かつ **max 500m**
- 減らした分を Main または Pre-Main にシフト

---

### C. 本数・項目数の適正化

| 現状の傾向 | 推奨スタイル（Quick 参照） |
|------------|----------------------------|
| 20×50m で 1000m | 4×200m、2×400m 等の長距離セット |
| Drill 15×50m | Drill 8×50m、6×100m 等に抑える |
| Kick 16×50m | Kick 4×100m、6×100m、4×200m |
| Pull 12×100m | Pull 4×200m、3×400m 等 |

**プロンプト指示案**:
- 「距離を満たすためには本数より**距離単位を大きく**する（50m×20本より 200m×4本、400m×2本）」
- 「各ブロックのセット数は**過度に細かくしない**。1ブロックあたり 1〜2 セッション、各セッション 4〜12 本程度を目安」

---

## 実装タスク（優先順）

1. **buildBlockAllocation の調整**
   - W-up: 12% → 8%、上限 500m
   - 差分を Main にシフト

2. **プロンプトの追加・修正**
   - W-up: 「1〜2セグメントで十分。SKPS/IM Order/Variable 等を必ず含む。距離を稼ぐ目的でセグメントを増やさない」
   - 本数: 「少ない本数×長い距離を優先。50m×20本より 200m×4本、400m×2本」
   - Quick テンプレの出力例を「参照スタイル」として system に含める（1〜2例）

3. **menu-dictionary の拡充**
   - Quick テンプレから抜粋した良い表現を追加
   - コーチングキュー（｜1-4 Dec、｜good kick）の使用を推奨

4. **CORE_SYSTEM_PROMPT の文言更新**
   - 「チープ禁止」をより具体的に（Quick との比較を明示）
   - ブロック構成の「2〜3段階」を「1〜2セッションで目的を持たせる」に調整（W-up に限定）
