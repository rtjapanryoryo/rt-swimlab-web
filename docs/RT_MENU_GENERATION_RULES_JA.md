**プロトコル（思想・定義）とジェネレート（生成手順）はこの1つ。今後はここを更新して仕様を変えていく。**

参照するのは次の3つのみ：
1) **本ドキュメント**（プロトコル＋ジェネレート）
2) **共通メニュー辞書**（content/common 等）
3) **クイック用コンテンツ**（content/quick：PDF・menu-templates-9.json 等）

# Part 1：プロトコル（思想・定義・絶対ルール）

## 指導思想（最優先）

- 練習は **「目的 → 強度 → 理由」** の順で考える。**量より質。フォームを崩して強くしない。**
- **安全第一**（年齢・性別・疲労を最優先）。年齢・疲労は期より優先する。
- 主役は選手。追加練習で追い込まない。判断に迷ったら強度を下げる。
- 怖がらせない・ネガティブ発言禁止・故障させない。

## 期の定義（①〜⑦）

1. **リカバリー期** … 回復・感覚維持・姿勢安定  
2. **基礎形成期** … 水感覚・姿勢・呼吸・フォーム固め  
3. **発展形成期** … 技術精度向上・スピード導入  
4. **強化期 (スピード持久力)** … ボリュームと心肺土台  
5. **強化期 (耐乳酸)** … 乳酸耐性・レースペース持続  
6. **調整期** … 疲労除去＋スピード維持  
7. **テーパー期** … 神経調整・反応・仕上げ  

## 期ごとの内容・強度制御（カスタム専用）

各期で「目的（期の役割）」と「内容・強度」がズレないことを最優先にする。

- **Dive** … 調整期・テーパー期が中心。リカバリー・基礎形成・発展形成・スピード持久・耐乳酸期では入れない。
- **耐乳酸MAX** … 耐乳酸期のみ明確に実施。他期では入れない。
- **リカバリー期** … Diveなし。強度を落とし、フォーム・姿勢・リズムの再構築に集中。上級者は量を落としすぎない。
- **基礎形成期** … Diveなし。耐乳酸MAXは原則入れない。内容と強度表記を必ず一致させる。
- **発展形成期** … Diveなし。技術×持久の積み上げに集中。
- **スピード持久期** … Diveなし。耐乳酸MAXは入れない。スピード×持久までに留め、最大耐乳酸刺激は行わない。
- **耐乳酸期** … 現状の設計を維持。内容・構成ともに問題なし。
- **調整期** … Diveを少しずつ導入可。メイン後に行うか途中に挟むかはチーム方針による。
- **テーパー期** … 耐乳酸セットは入れない。Diveでテンポアップ・レース動作の最終調整を行う。

### 期別・距離タイプ別トータル距離基準（120分・高校生以上〜全国大会）

| 期 | S | M | D |
| --- | --- | --- | --- |
| リカバリー | 3000m | 3500m | 4000m |
| 基礎形成 | 4000m | 5000m | 6000m |
| 発展形成 | 5000m | 6500m | 8000m |
| スピード持久 | 5000m | 7000m | 8500m |
| 耐乳酸 | **5000m** | 6000m | 8000m |
| 調整 | 3500m | 3500m | 6000m |
| テーパー | 3000m | 3500m | 4000m |

**思想**: 期が進むにつれて量を上げる。**耐乳酸期は強度とボリュームの両立**を図り、120分練習ではSタイプでも約5000m規模を確保。Main以外のブロック（W-up/Kick/Pull/Pre-Main等）でも距離を積み、全体で目標距離に届くこと。調整・テーパーで段階的に削る。60分・90分は時間比でスケール（例: 60分≈50%、90分≈75%）。

### 期別強度の天井（①〜⑦）

| 期 | メイン上限 | 非メイン上限 |
| --- | --- | --- |
| リカバリー | ③ | ③ |
| 基礎形成 | ④ | ③ |
| 発展形成 | ④ | ④ |
| スピード持久 | ⑤ | ④ |
| 耐乳酸 | ⑥ | ④ |
| 調整 | ⑤ | ④ |
| テーパー | ④ | ③ |

**原則**: 期ごとの最大強度はメインが担う。非メインブロックは原則「−1段階」まで。耐乳酸期のみメイン⑥、それ以外④止まり。ボリュームアップ＝無制限に強くする、ではない。

### 全期共通ルール（神経刺激）

- 練習の最後（W-down前）に **25m×2本 MAX** などを入れてもよい。強度⑦（パワー・スピード）を入れてOK。量ではなく「神経刺激」が目的。

## 強度目安（10秒心拍）

- A1: 22〜24 / A2: 24〜26  
- EN1: 26〜27 / EN2: 28前後 / EN3: 29〜30  
- AN系: 短時間のみ  

**年齢補正**: 小学生 +2〜3 / 中学生 +1〜2 / 高校・大学 基準 / 成人 -2〜3  

## 構造（絶対）

**W-up → Drill → Kick → Pull → Pre-Main →（休憩 or Easy）→ Main → Down**

構造を崩したらRT-japan式ではない。必要時のみ Main 前に休息 or Easy を入れる。

### 総距離とブロック合計の一致（必須）

**各ブロックの距離合計と total（総距離）は必ず一致させる。** ブロックごとの距離×本数×セットを合計し、その値を total に記載する。計算ミスや不一致は禁止。

### Pre-Main と Main の強度差（必須）

**Pre-Main は Main より一段階抑えた橋渡し役。** Main が④なら Pre-Main は③、Main が⑤なら Pre-Main は④、Main が⑥なら Pre-Main は④〜⑤程度。Pre-Main で Main と同じ強度にしない。

### ブロックの複数構成（推奨）

各ブロックを1メニュー完結型にせず、期に応じて複数メニューで構成する。

| ブロック | 構成の目安 |
| --- | --- |
| **W-up** | 目的は段階的に体を作ること。**2〜3段階**に分けた構成（例: 200m A1 → 200m SKPS A1 → 100m Build）。 |
| **Kick** | 目的は下半身の土台づくりと期テーマへの接続。**発展形成期・スピード持久期・耐乳酸期では2構成**。 |
| **Pull** | 目的はフォームと出力の安定を作ること。**Fr中心で2構成**、質の違いを持たせる。 |
| **Main** | 目的は段階的に強度を引き上げること。**基礎形成期以降は Pre-Main を含めて3段階程度**（例: Pre-Main④→Main前半④→Main本編⑤）。 |

### Main の強度割合管理（耐乳酸期）

耐乳酸期の Main では、**④以上の割合**や**⑥の総距離目安**を軽く設定する。例: ⑥は総距離の○%以内、④〜⑤で橋渡しを確保。期の役割を明確にする。

## 種目・W-up/Down

- **W-up と Down の種目は Cho のみ。** 本文に Fr/Fly 等を書かない。
- **※Cho は「内訳（Fr/Ba/Br/Fly/IM 等）」を書かない。Cho とだけ記載する。**
- 他セクションは条件の種目（Fr/Ba/Br/Fly/IM）。Rest の種目は -。
- **Rest の内容**は「Rest / Free time（5~10min）」で表記する（不要時は空文字。代替で Easy Swim 〇〇m（A1）可）。
- **Pre-Main・Dive は廃止しない。** 表では種目・内容が空のときは「-」とせず空欄で表示する。

## 絶対ルール（運用）

- 追加練習で追い込まない  
- 推測での捏造禁止（サークル等は入力・資料にない値で創作しない）  
- 入力不足なら生成せず、不足項目を列挙して停止

# Part 2：ジェネレート（生成手順）

## 0) 入力不足チェック（不足なら停止）

必須項目：期 / 種目 / 性別 / 年齢 / 距離タイプ(S/M/D) / レベル / 目的 / 状況 / 練習時間(60/90/120) / ボリュームアップ項目

### 追加: ボリュームアップ項目の定義（必須）

- 「ボリュームアップ項目」は **Drill / Kick / Pull / Pre-Main / Main のいずれか1つ** を選ぶ。
- 増やし方は **距離**（例: Kick +200m）。指定がなければ増やさない。
- 合計距離の増減は、**既存テンプレから大きく外れない範囲**に留める。

## 1) 出力構造（順序固定・省略禁止）

- 【目的】（1行で明確に）
- W-up **（種目は Cho のみ。本文に Fr/Fly 等を書かない）**
- Drill
- Kick
- Pull
- Pre-Main
- （休憩 or Easy）
- **Main（カテゴリ明記：ベース／ベストアベレージ／ダイハード／耐乳酸MAX／Standard Main）**
- Down **（種目は Cho のみ。本文に Fr/Fly 等を書かない）**
- Total：合計距離のみ
- 練習意図（2〜4行）
- 指導ポイント（箇条書き3つ）
- 注意点（箇条書き3つ）
- 期待効果（2〜3行）

**種目ルール**: W-up と Down だけ種目を **Cho** に固定。Cho のときは内訳（Fr/Ba/Br/Fly/IM 等）を書かず「Cho」とだけ記載する。他セクションは条件の種目（Fr/Ba/Br/Fly/IM）、Rest は -。出力は毎回この形式の新規生成とする。

## 2) Main選択の絶対ルール

- 期の目安に反するMainカテゴリは禁止
- 年齢補正を最優先（特にマスターズは安全側。フォームを崩して強度を上げない）
- **距離タイプ整合**：S=50–100 / M=100–400 / D=400+

### 追加: 期×Mainカテゴリの許容（目安）

- **リカバリー期** … ベース / Standard Main（高強度は禁止）
- **基礎形成期** … ベース / Standard Main（技術優先）
- **発展形成期** … Standard Main / ベストアベレージ（短い刺激）
- **強化期 (スピード持久力)** … ベース / Standard Main / ベストアベレージ（量を確保）
- **強化期 (耐乳酸)** … Standard Main / 耐乳酸MAX / ダイハード（年齢・疲労を最優先）
- **調整期** … Standard Main / ベストアベレージ（量を抑える）
- **テーパー期** … ベストアベレージ（短く鋭く）。耐乳酸MAX・ダイハードは原則禁止

迷ったら強度を下げ、Standard Main に寄せる。

## 3) クイック生成の原則

- **クイックのメニューは quick-algorithm からだけ** … クイックで作り出す練習メニューは**すべて** `content/quick`（quick-algorithm.pdf と menu-templates-9.json）から抽出する。
- **距離タイプを最優先に振り分ける** … まず **距離タイプ（S=ショート / M=ミドル / D=ディスタンス）** を主軸に分岐する。ここが最優先ルール。
- **9通りテンプレから1つを選ぶ** … 「【アプリ】自動生成メニュー - 9通り」をJSON化した `content/quick/menu-templates-9.json` を固定テンプレ群とする。距離タイプで S/M/D のいずれかのグループに振り分けたあと、残りの条件（期・種目・年齢・レベル・目的・状況・練習時間・ボリュームUP・性別）でそのグループ内のどれに当てるかを決める。テンプレが無い・空の場合はメニューを出さず「テンプレを設定してください」と案内する。
- **基本はファイルの情報からそのまま抽出** … 捏造せず、quick-algorithm（PDF・JSON）に書かれた情報から選ぶ。
- **形式はアプリケーションを軸に** … 出力はアプリのメニュー表形式（セクション・距離・本数・種目・内容・強度・Total 等）に合わせる。表示される表の形を崩さない。
- **組み合わせなど高度な生成** … 単一候補の選択に加え、複数候補の組み合わせや条件に応じた組み替えなど、ファイル情報を活かした高度な生成も期待する。ただし推測・創作は禁止。

## 4) クイックの骨格決定（テンプレ固定化を防ぐ）

- 距離タイプ×時間×レベル×期×目的から、距離テンプレを「2〜4候補」抽出し、その中から「1つ選ぶ」
- 直近と同じテンプレになりそうなら、必ず「2番手候補」に切り替える
- 合計距離はテンプレを維持。調整はPre-Main/Mainの"質"に限定（距離の大崩れ禁止）

## 5) 多様性ルール（必須）

- 各ブロック（W-up/Drill/Kick/Pull/Pre-Main/Main/Down）は、辞書の該当カテゴリから「最低3候補」を内部で用意し、その中から「1つ選んで採用」する
- 同一入力条件で直近2回と「Mainの型」が同じ場合、必ず再生成：Mainカテゴリ もしくは Pre-Main型 もしくは Drill型 のいずれかを変更（距離骨格は維持）
- 固定ワード（SKPS/IM order/Des/ALT等）は使ってよいが、毎回同じ並びのコピペは禁止
- 目的が同じでも刺激の入れ方をローテ（Pre-Mainで入れる／Mainで入れる／Drillで入れる 等）

### 追加: 多様性・再生成ルールの実装条件

- **候補の扱い**: 最低3候補を内部で用意するが、**候補一覧は最終出力には出さない**。選ばれた1つのみを出力する。
- **履歴（直近2回）が取れない場合**  
  - ① 距離テンプレは常に**2番手候補**を選ぶ、または  
  - ② その日のローテーションID（A/B/C）を入力し、ブロックパターンを切り替える。

## 6) カスタム（APIあり）の追加ルール

- クイック骨格は維持したまま、理由・意図・指導ポイントの精度を上げる（"それっぽい創作"は禁止）
- 変化が出ない場合は探索を増やす（例：temperatureを少し上げる）※型と安全は崩さない
